# Demonstration of using React and Flask together
A common situation is to have a legacy web-application written in a different framework, than the 
current en vogue way of writing applications. Flask is a HTML template generating framework, while React is a 
more modern front-end framework. Often the desire is to improve the front-end but preserve the back-in business logic. 
(It is generally riskier to re-engineer long working business processes, than to re-engineer user interfaces. A broken business process
is far more likely to cause signicant harm to a company than an disgruntled user.) So this demo assumes the scenario
that we need to preserve some business process functionality, like interacting with the order database, while creating a
better user interface. 

The React solution results in an application running in the users browser. This applicaiton then makes REST calls to the back-end business processes. This inverts the client server role assignment typically assumed with browsers and web servers. Indeed, the architeture can better be considered as server to server. 

Rather than describing how to change an exisitng interface, we will just show adding new functionality to an existing app. In our case, we will be adding a report page to our app that will just return the number of registered users in the app. No authentication or security checks are required.


## The flask application
In our demo the back-end is written in Flask and handles all interactions with the database and any other services used to implement
the business transactions. A typical Flask application will handle the business process and then redirect the user to an html template that 
provides the user interface to whatever data is yielded from the process. In our demo, we will assume the flask endpoint has already been refactored so that the 
business functionality is in a method evaluation and then returns the template. The method can then be exposed in its own endpoint that expects the parameters of the
method call to be provided in a JSON document. We can collect these isolated business process endpoints into an API and indeed we can place all the endpoints under `/api`.

The demo has an extremely limited business functionality implementation with only a single endpoint, `/api/users` that takes no arguments. It always returns `{"Users": 2}`.

We will have to deal with CORS in this example, but we will simply the issues for the demo by allowing all endpoints to be allowed by CORS. 

## React Application
The React application is where we would normally have very slick user interface experience. However, we have a very simiplified React application because we want to focus on the interactions of the React application with the Flask app. So as the Flask functionality is very limited, so too is the React app. 

The React app will display one component with the results of calling the Flask `/api/users` endpoint. 

## Project structure
If one were to add react front-end onto an existing Flask app, one might use something like the example that postulates putting a React front-end on the Flask tutorial application flaskr.

```
flaskr-react/
├── api/                 # Flask backend
│   ├── flaskr/          # Your existing Flask code
│   ├── instance/        # Flask instance folder
│   └── requirements.txt
└── front-end/            # React frontend
    ├── public/
    ├── src/
    ├── package.json
    └── ...
```

Our demo will use a much flatter structure. 

```
├── app.py                      # Flask backend; endpoint /api/users
├── front-end
│   ├── node_modules            # create-react-app stuff
│   ├── package-lock.json       #   ...
│   ├── package.json            #   ...
│   ├── public                  #   ...
│   ├── README.md               #   ...
│   └── src                     # our react front-end source files (.js, .json, etc.)
└── README.md
```

The flask application is in a single file `app.py` located in the root of the project. To support this pythong project you would normally have a python venv environment into which you would install flask and flask-core.  This will allow you to run the python applicaition with the command `python ./app.py`

The React application is in the front-end subdirectory containing the infrastructure created from using the now deprecated Create React App envirionment. It was generated by running `npx create-react-app front-end`

Inside the front end we have made changes to the default `App.js` component and added a `UserCount.js` component.

We have also added some nicer looking css changes to `index.css` and added `tailwind.config.js`.

## Running the project
In one shell start the flask app, `python3 ./app.py` and in another shell start the react front-end app, with `cd front-end; npm start`. Use http://localhost:3000 to see the react app. 

You can edit code in either app and when saved the respective app will reload automatically. This allows you to experiment with each app to obverve how the code interacts with each other, or even develop new endpoints and components interactively.
